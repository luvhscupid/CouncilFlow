# CouncilFlow research

These documents are non-normative research and planning records, not approved
features or independent implementation authority:

- [Token and context efficiency](AI-Agent-Token-and-Context-Efficiency-2026-11-15.md)
- [Draft efficiency implementation phases](Agent-Efficiency-Implementation-Phases-DRAFT-2026-11-15.md)
- [Model selection and xKiro](Universal-Model-Selector-xKiro-GPT6-Haiku-2026-11-15.md)

CouncilFlow remains an installable multi-agent workflow skill for existing AI
coding environments, currently Codex-native. Claude Code support is a possible
extension, not a verified feature; plugin packaging depends on host support.
The roles use host models, tools, permissions and native delegation. They do not
require independent role servers or processes. CouncilFlow is not a standalone
AI agent, coding assistant, orchestration platform/runtime, provider, gateway,
billing service or SaaS application, or a replacement for the host and its
native delegation.

Memory, efficiency, model-selection and xKiro proposals require explicit Owner
authorization before implementation, installation, experiments or spending.
Authorized supporting scripts, utilities, schemas and optional adapters may
extend the skill/plugin ecosystem without silently becoming a standalone platform.

The [controlling Gate 3 Owner Charter](../gate3/CouncilFlow-Gate3-v0.2/01-OWNER-CHARTER.md),
existing Owner decisions, frozen specifications and role policies remain
authoritative. Preserve the approved architecture and responsibilities; research
does not redefine them. Historical research and frozen Gate 3 records remain
unchanged. See the [root project contract](../../AGENTS.md) and
[current skill](../../.agents/skills/council-flow/SKILL.md) before proposing changes.
