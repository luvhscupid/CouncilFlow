# Slice 04 | Measure cost, quality, and next architectural decision

**Status:** PROPOSED; NOT AUTHORIZED. Requires demonstrated working host flow and preapproved experimental budget.  
**Target:** AR-10; possible simplifications are hypotheses, not automatic work.

## Comparison design

- Freeze a representative sample of coding tasks **before** running. Match tasks and initial code states for ordinary host-native coding versus CouncilFlow. Include at least one small, one moderate, and one failure/rework scenario.
- Owner chooses sample size, allowed models/routes, expense/time ceiling, and valid comparison rules in advance. Do not present an invented threshold as approved.
- Record session/host versions, effective model, retries, test outcomes, accepted functional criteria, bug severity, end-to-end effort, tokens where host reports reliable usage, and direct human courier interventions.
- Distinguish provider billing from estimated token counts, and measures from claims. Efficiency helpers stay opt-in; no API credentials or paid subscriptions are required by this roadmap.
- Normalize quality judgments against the same frozen acceptance criteria and independent verification on each path. Report blind spots, confounders, missing data and task-by-task variance; do not force a positive improvement percentage.

## Deliverables

1. Reproducible fixture/task descriptions and actual raw-to-summary evidence mapping.
2. Side-by-side quality, effort, tokens (if reliable) and failure/rework comparison.
3. Decision proposal: preserve current mandatory roles; simplify optional ceremony; improve native capability checks; consider stricter provenance only if measurable and host-capable.
4. A short prioritized **new** roadmap requiring Owner approval, rather than automatic continuation.

## Acceptance gate

- [ ] Owner-approved experiment scope, cost ceiling and sample size recorded before execution.
- [ ] Task baseline, metrics and interpretations can be audited independently.
- [ ] Findings separate measurements from assumptions and disclose missing/incomparable data.
- [ ] No automatic protocol downgrade, reduced verification roles, mandatory hook or architecture pivot.
