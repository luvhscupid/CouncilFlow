# Mission control visual system

Operate mode: the evidence ledger is the main visual anchor. A quiet graphite workspace, cool blue acceptance segments, warm amber uncertainty and readable textual lifecycle labels support quick inspection. No simulated live motion, gradients, glass, glow, photos or decorative charts.

Tokens live in styles.css: graphite #11151b, surface #181e26, raised #202834, rule #303b49, ink #edf2f8, secondary #a2b0c2, blue #82b8ff. Semantic green, amber and red supplement explicit text and symbols. Light mode overrides the same tokens.

Local Segoe UI Variable / Segoe UI typography avoids external font requests and works with the Windows environment. Cascadia Code / Consolas is reserved for identifiers, timestamps and command evidence. One dense workspace, consistent gutters, 6–8px radii, restrained dividing rules. The Owner's offline and no-external-service constraints take priority over skills requesting downloaded fonts or visual assets.

Desktop: navigation rail; run overview with acceptance and current recorded operation; five role summaries; candidate ledger beside a bounded event console; verification and reported resources. Mobile: status and acceptance first, operation and blockers before stacked expandable roles, ledger, console and evidence. The nine-step workflow retains its actual repeated Manager/Planner handoffs.

Focus outlines use the blue token. All actionable surfaces are native buttons, links, details or selects. The evidence drawer uses native dialog focus containment and restores focus. Reduced motion removes transitions and smooth scrolling. No automatic animation or periodic event generation occurs.

Directions considered: terminal-first timeline, role-first topology, evidence-first ledger. Selected the ledger because it separates verified completion from apparent agent activity. Activity and role state are secondary, timestamped assertions.
