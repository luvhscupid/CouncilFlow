# R6-Claude: Architecture Specification v0.3 (draft for Owner approval)

**Tags:** **[A]** agreed by the council and Owner, **[H]** untested hypothesis, **[E]** external documentation evidence. No probes were run and nothing was modified. My Codex findings come from web search only, mostly third-party sources, so they are leads for P0, not facts.

## 1. Components and authority

| Component | Is | May | May never |
|---|---|---|---|
| **Owner** | Human | Approve plans, grant waivers, accept results | n/a |
| **Planner** | LLM | Write contracts, outcomes, checks | Write runtime state, loosen criteria alone, grant waivers |
| **Manager** | Python + SQLite | All state transitions, dispatch, budgets, verification, risk floors | Delegate policy or verification **[A]** |
| **Worker** | Codex CLI agent | Edit inside its workspace | Self-report success as evidence, see hidden checks |
| **Analyzer** | Checks run by the controller, optional LLM review | Execute frozen checks, cite evidence | Use the Worker's self-assessment |

## 2. Contract vs. runtime state

- **Contract:** immutable, versioned, hash-locked, written by the Planner and admitted by the controller **[A]**.
- **Runtime state:** attempt IDs, PIDs, manifests, evidence, incidents, waivers and approvals, outcome statuses, resolved model IDs, costs. The Planner never writes any of it.
- **Waivers live only in runtime state.** A Planner-written contract can't request its own safeguard exemptions.

**Changes from v0.2** (the rest is unchanged):

```json
"risk":        {"task_tier_proposed": "low"},
"execution":   {"backend": "profile:codex.exec", "commands_hint": ["python","pytest","ruff","git"]},
"exposure":    {"requires": ["workspace_write_confined","controller_data_unreadable",
                             "env_scrubbed","kill_tree_confirmed","egress_provider_only"]},
"change_policy": {"max_files": 10, "max_bytes": 200000, "allow_binary": false,
                  "allow_symlinks": false, "allow_submodules": false, "allow_mode_changes": false},
"acceptance":  {"executable_outcomes": "all_verified", "manual_outcomes": "owner",
                "report_coverage_gaps": true}
```

- **Task risk** is the consequence of wrong output. The controller computes the effective tier as `max(planner, rule floor, diff-derived)`. It can fall after a revert; incidents persist **[A]**.
- **Execution exposure** is computed from the proven enforcement manifest, never declared. The result is `contained`, `partial(egress)`, or `refused`.

## 3. Containment decision (your R6 challenge)

I accept the split between result integrity and execution containment. Integrity comes from extract-and-verify. Containment is a separate set of requirements:

| Requirement | Waivable? |
|---|---|
| `workspace_write_confined` | **No** |
| `controller_data_unreadable` | **No** |
| `env_scrubbed` | **No** |
| `kill_tree_confirmed` | **No** |
| `egress_provider_only` | **Yes**, only if effective tier is low. Needs a per-task Owner waiver event. The report marks it `containment: partial` and lists what was waived. |

- Unproven non-waivable requirements mean dispatch is **refused**. No silent downgrade.
- **Hidden checks:** they never sit in the worktree and are materialized only after the Worker is confirmed dead. Since `controller_data_unreadable` is mandatory, hidden-check isolation follows from it, and no separate disable rule is needed. If you'd rather keep your "disable when isolation isn't proven" rule as a redundant guard, I won't object.
- **Open question:** whether Codex's own sandbox (which wraps the model's shell commands) can meet these. The Codex process itself runs outside that boundary **[H]**.

## 4. Extract-and-verify

1. Confirm the Worker process tree is dead (§6). Otherwise → `UNKNOWN_LIVENESS`.
2. Using the controller's own git binary and config (never the Worker's `.git` config or hooks), compute the change set against the recorded base commit.
3. **Validate the change manifest** (GPT amendment A):
   - base commit matches the record
   - paths normalized: no `..`, no absolute paths, with Windows case-insensitivity, 8.3 short names, alternate data streams and reserved names handled
   - no symlinks, junctions or other reparse points, submodule changes, mode changes or binary changes unless `change_policy` allows them
   - file and size caps respected
   - every path ⊆ `scope.write`, and none in `frozen_paths` or `forbidden_paths`
4. Any violation: **incident**, revert to the checkpoint, and classify as contamination.
5. Create a clean scratch checkout at the base commit, with hooks disabled.
6. **Copy only the validated files' contents** into it (no applying arbitrary patches).
7. Materialize hidden payloads.
8. Run checks under the controller's identity with a scrubbed environment and timeouts. `read_only` checks get a before/after tree hash.
9. Record evidence (exit code, raw output refs, tree hashes, live/mock tag). Coverage is recorded as support only **[A]**.
10. Compute outcome statuses.

## 5. SQLite consistency model

- The controller is the single writer, and the DB sits outside the Worker's reach.
- WAL mode with `synchronous=FULL`.
- `events` is append-only, enforced by triggers.
- **Each event and its state projection commit in one transaction.**
- **Intent → side effect → outcome:** intent events carry `UNIQUE(attempt_id, action)`. A startup reconcile pass resolves every intent that has no outcome.
- JSONL is a derived export only **[A]**.

## 6. Dispatch, process ownership, recovery

- Each dispatch gets a new `attempt_id` (the fencing token), a fresh worktree, and a scrubbed environment. Reports with a stale `attempt_id` are discarded.
- **Windows process ownership [H]:** a Job Object with kill-on-close owns the Codex tree, and the controller records PID and creation time. Whether sandboxed children can escape the job must be tested.
- **Liveness is never assumed.** Process absent with a mismatched creation time → dead. Present → kill the tree and confirm. Unconfirmable → `UNKNOWN_LIVENESS`: no redispatch, no workspace reuse, wait, then escalate **[A]**.
- **Crash recovery:**

| Last event | Action |
|---|---|
| `DISPATCHED`, no report | Confirm dead. If the tree hash differs from the checkpoint, restore. Fresh redispatch, with its own `crash_recoveries` cap. `idempotent: false` → escalate. |
| `REPORTED` or `VERIFYING` | Rerun `read_only` and `isolated_mutation` checks only. `external_side_effect` checks are never auto-rerun. |
| Checkpoint intent with no outcome | Verify the ref exists, else recreate from the last good state. |

- **Checkpoints** are refs in a private namespace or snapshots, never commits on the user's branch **[A]**.

## 7. State machine

```
Step: PENDING → READY → [containment gate] → DISPATCHED → REPORTED → VERIFYING ─pass→ PASSED
        containment unproven → REFUSED         │ stuck → UNKNOWN_LIVENESS → ESCALATED
        needs out-of-scope access → BLOCKED → ESCALATED
        VERIFYING ─fail→ classify by rule ─→ RETRY_PENDING | ESCALATED(planner|owner)

Task: DRAFT → ADMISSION → AWAITING_PLAN_APPROVAL → RUNNING ⇄ AWAITING_OWNER
      → DONE_VERIFIED | AWAITING_OWNER_ACCEPTANCE | DONE_PARTIAL | FAILED | ABORTED
```

## 8. Failures and retries

| Class | Detected by | Action |
|---|---|---|
| Infra | Timeout, missing dependency, provider error | Own cap; doesn't consume Worker retries |
| Contamination | Out-of-scope or frozen path touched, regression, manifest violation | Immediate clean redo |
| Check flaw | Check fails against known-good state | Escalate to the Planner |
| Implementation | Executable check fails | Retry 1: incremental repair with the failure evidence as new input. Retry 2: fresh worktree and session. |
| Unknown | None of the above | One incremental retry, then Planner, then Owner |

- A fingerprint repeating twice triggers escalation, as a signal not a verdict **[A]**.
- Codex's `exec resume` can be used for incremental repair only. A clean redo always starts a new session **[H]**.

## 9. Verification and acceptance rules

- Only the controller sets an outcome to `verified | weak | unverified | contradicted`. A Worker report is never evidence **[A]**.
- Worker-authored tests don't count as evidence unless adopted by an approved amendment.
- Tier ≥ medium needs at least one end-to-end objective check. Hidden checks are required when tier ≥ medium and the outcome is behavioral.
- `DONE_VERIFIED` requires every executable outcome `verified`. Manual outcomes → `AWAITING_OWNER_ACCEPTANCE`.
- **Every report lists `unverified`/`weak` outcomes and coverage gaps first.** Passing checks do not equal fulfilled intent (amendment E).
- Amendments can't loosen outcomes, checks, scope, limits or gates without Owner approval, and the controller decides what counts as loosening.
